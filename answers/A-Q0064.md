## 答题逻辑（中文，3–5 步）
1. 定义：负载增长时，靠加容量而不是重新设计，就能保持响应时间和正确性。
2. 手段：无状态服务横向扩展、异步削峰、缓存挡数据库、数据分区避免单点。
3. 例子：VV / AI Park（Spring Cloud + Kafka + 缓存 → 毫秒级）；Sohu 的 Redis 集群；Baidu 的 Dubbo 重构。
4. 取舍：一致性、运维复杂度。

## 30s
> To me, a highly scalable system keeps its response time and correctness as load grows, by adding capacity rather than redesigning. That means stateless services that scale horizontally, asynchronous processing to absorb spikes, caching to protect the database, and data partitioned so no single node becomes the bottleneck. At VV Technology and AI Park I built exactly that — Spring Cloud microservices, Kafka and caching — and got service processing to the millisecond level.

## ATL — 60s
> For me, scalable means you can add load by adding capacity, not by redesigning — and correctness holds while you do it. The building blocks: stateless services that scale out; asynchronous processing so spikes queue up instead of failing; caching so the database isn't the bottleneck; and partitioning, so no single node limits you. At VV Technology and AI Park I built platforms that way: Spring Cloud microservices, Kafka for asynchronous flows, and caching with cache-breakdown protection, which brought service processing to the millisecond level. At Sohu I moved our CMS from a memcached cluster to a Redis cluster, and at Baidu I re-architected an order system onto Dubbo microservices. The price is consistency and operational complexity — so I only take on as much distribution as the load really needs.
