## 答题逻辑（中文，3–5 步）
1. 原则：同一套门禁，不走捷径，也不额外信任。
2. AI 特有风险：漏边界条件、编造 API 或版本、引入不安全写法。
3. 规则：不让 AI 同时写代码和验证它的测试。
4. 性能敏感代码要有证据（benchmark / 压测）。
5. 合并的人负责。

## 30s
> AI code goes through the same gates as human code — no shortcuts and no extra trust: unit and integration tests, SonarQube, security scanning and human review. On top, I watch the AI-specific risks: missed edge cases, invented APIs or library versions, insecure patterns. One rule: the AI shouldn't write both the code and the tests that prove it. And whoever merges it owns it.

## ATL — 60s
> My principle is simple: AI-generated code passes exactly the same gates as human code. In our pipeline that means JUnit and integration tests, the SonarQube quality gate, automated regression and penetration testing, and a human review before merge. Then I add checks for the risks that are specific to AI. It often looks right but misses edge cases, so tests must cover the failure paths. It can call APIs or library versions that don't exist, and it can bring in insecure patterns — that's what static analysis and review are for. For performance-sensitive code we need evidence: a benchmark or a load test, not "it looks fine". And ownership doesn't move: if you merge it, you own it.
