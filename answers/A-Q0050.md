## 答题逻辑（中文，3–5 步）
1. 一条分界线：共享的只建一次，不同的做成可配置。
2. 共享：核心账务、风控引擎、数据模型、API 层、配置管理。
3. 本地化：监管报送、KYC 规则、本地支付通道、货币和语言。
4. 目标：开新市场是做配置，而不是重做。
5. 证据：GBD 的多租户 SaaS（PA-10.1 / 10.2）。

## 30s
> I draw one line. What every market shares — core accounts, the risk engine, one data model, the API layer, configuration management — is built once. What differs — regulation and reporting, KYC rules, local payment channels, language — becomes a configurable layer. Opening a new market should be configuration, not a rebuild. I built that kind of platform at Golden Bridge: one multi-tenant SaaS core with configurable KYC and payments.

## ATL — 60s
> Architecturally: a shared core, built once — core accounts and ledger, the risk engine, one data model, a common API layer and shared services. Market differences sit in a configuration layer: regulatory reporting, KYC rules, payment channels, currency and language, driven by tenant and market configuration rather than code branches. Where a rule can't be configured, it goes behind a clear extension point, so one market's change never forks the core. At Golden Bridge I architected this pattern: a multi-tenant SaaS on Spring Cloud and Kubernetes behind an API gateway, with hierarchical KYC designed for multi-country coverage, and configurable rules for authentication levels and bonuses.

## SM — 60s
> The decision that matters is where to draw the line, because it sets the cost of every future market. I'd agree it with the business up front: what is common across markets, and what is genuinely local. Common parts get built once and owned centrally; local parts become configuration, owned together with each market's compliance team. Then a new market is a configuration project with a known cost and timeline, not a new build. I've built that kind of shared, configurable platform before, at Golden Bridge, and in a small team it's the only way to keep up.
