## 答题逻辑（中文，3–5 步）
1. 三个原则：保留现有控制、输出可验证、总有退路。
2. 服务本身：PR → three-dot diff → headless agent，四个维度，和 SonarQube 并行。
3. 治理：AI 只建议、不批准不合并；正式的架构和风险审批；2026-05 上线。
4. 结果：senior review time **估算**减少约 80%，讲公式。
5. 【SA-03 / SA-04 入库后启用】数据边界；试点后推广。

## 30s
> At UOB I designed and built an AI code-review service that's in production. On every pull request, a headless Claude Code agent reviews the diff for security, performance, correctness and maintainability, alongside SonarQube, and posts comments to the PR. The rule I set: the AI advises, a human approves and merges. We estimate it cut senior engineers' review time by about 80%.

## ATL — 60s
> Three principles: keep the existing controls, make the AI output verifiable, and always have a fallback. Concretely, a Spring Boot service picks up each pull request, takes the three-dot diff and runs a headless Claude Code agent through ProcessBuilder. It reviews four dimensions — security, performance, correctness and maintainability — next to SonarQube, so deterministic analysis and the LLM back each other up. Comments go back on the PR; the agent can never approve or merge. I improved the prompts through A/B testing. Result: an estimated 80% cut in senior review time.
> 【SA-03 入库后启用：It runs in an isolated, read-only environment with no outbound network access. Code never leaves the bank's network, the model endpoint is in-region, and prompts and outputs are logged.】

## TPM — 60s
> I'd describe it as a controlled rollout of a new tool in a regulated bank. I designed and built an AI code-review service and took it through formal architecture and risk approval before production; it went live in May 2026. The governance rule was fixed from day one: AI comments are advisory, and a human reviewer approves every merge. On results, I'm careful: we estimate senior review time fell by about 80%, because human review rounds dropped to one or two per PR and each round is shorter — the AI clears syntax and basic issues first.
> 【SA-04 入库后启用：We started with one squad, collected feedback and tuned the prompts to cut unnecessary findings, then expanded.】

## SM — 60s
> I treat AI as a productivity investment that has to pass the same governance as anything else. As the team grew, code review became a bottleneck: senior engineers spent too long on repeat issues, and quality was inconsistent. So I designed and built an AI code-review service, took it through formal architecture and risk approval, and set one rule — the AI advises, humans decide. It's been live since May 2026, aligned with MAS FEAT principles, and I briefed senior management on it. We estimate it cut senior review time by about 80%. The value isn't only speed: reviewers now spend their time on design and risk.

## 追问与应对
- **Q**：What if the AI gives a wrong suggestion and the developer follows it? / **A**："It's advisory, not a gate — a human reviewer must approve every merge, so a wrong suggestion still has to get past a person."
- **Q**：How do you prove the value? / **A**：讲公式（PA-07 §8）：before = rounds × T；after = 1–2 rounds × 0.3T → 约 80%。**说明是估算**，不是测量数据。
- **Q**：Where does the code go — data residency? / **A**：【SA-03 入库后】不出行内网络、endpoint in-region、全量留痕；入库前不答具体细节。
