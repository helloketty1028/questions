# BNK — 跨境支付对账（ISO 20022）（行业知识，不是个人事实）

**用途**：Q-0040（对账系统设计）、Q-0036（一致性）。来源：你的旧准备稿 #1 / #4（JPM，2026-10），报文名称按 ISO 20022 / SWIFT 的通用定义整理。**这是设计知识，不等于你在 UOB 做过对账**——UOB 的 hub 不做对账（03 PA-01、CF-N4）；你做过的对账是 VV 的支付子系统（PA-11.2）。

## 1. 两侧数据
- **A 侧（本行账）**：支付交易表（唯一 ID、金额、币种、值日、对手、终态）；总账分录（GL）；报文网关的发送记录（pacs.008，存量链路是 MT103）。
- **B 侧（外部权威源）**：代理行对账单 camt.053（日终）/ camt.052（日内）/ camt.054（单笔通知），存量还有 MT940 / MT950；清算系统的 pacs.002 状态报文和日终文件；卡组织清算文件；第三方支付渠道的结算文件（多为 T+1）。

## 2. 四层对账
| 层 | 回答的问题 | 外部依据 |
|---|---|---|
| ① 报文层 | 发出去的报文，网络是否真的收到了 | admi.007（ACK）/ admi.002（拒绝） |
| ② 状态层 | 对方接受还是拒绝，现在走到哪一步 | pacs.002（ACSC / ACSP / ACCC / RJCT / PDNG）；camt.056 / 029 / 026 / 087；gpi Tracker |
| ③ 账务层 | 钱有没有动、动了多少 | camt.053 / 052 / 054：余额、条目、值日、UETR、汇率、费用 |
| ④ 内部层 | 交易表和总账是否一致 | 本行 GL（sub-ledger 与 GL 的对账） |

## 3. 匹配 key
UETR、EndToEndId，金额加币种，值日；camt.053 的 ElctrncSeqNb 出现断号，意味着有文件缺失。

## 4. Break 处理
分类 → 自动修复已知模式 → 人工队列（有负责人、有账龄）→ 根因反馈到上游。
