**行业适用**：BNK direct · INT transferable（编排 / 校验 / 状态跟踪类中台）

## Situation
- The bank needed one hub between its channels (Internet Banking, branch) and downstream systems (the SWIFT ISO 20022 MX flow, CASA and others).
- The hub does initiation, validation, enrichment and status tracking. Processing, clearing and settlement sit outside it.

```
Internet Banking ─┐                                   ┌─► SWIFT ISO 20022 (MX) flow
Branch channels ──┼─► Payment-initiation hub ─────────┤
                  │   • validation  • enrichment      └─► CASA, other downstream systems
Reference data ───┘   • authorisation (group/account/product)
(FX rate, account,    • channel admin
 customer)            • pain.002 status tracking
```

## Task
- O2: led the end-to-end design. O1: personally built the core modules.

## Action
- I designed the API contracts, orchestration, validation, enrichment and pain.002 status tracking.
- I integrated digital and branch channels, reference data, and vendor and third-party banking systems.
- I personally coded three cores: payment-transaction initiation; the corporate-role + user-role permission matrix (the hub's authorisation layer); and processing of payment status results returned by downstream systems.
- Stack: Java, Spring Boot, Apache Camel, event-driven integration.

## Result
- The hub carries the bank's ISO 20022 cross-border initiation in production (see S-001 for the migration outcome).
- It sits upstream of processing and settlement at a MEPS+ participant bank.

## 讲法差异
- **ATL**：边界划分（hub 不做清算结算）；权限矩阵的两维设计；pain.002 状态回传的处理与对账。
- **SM**：为什么把授权、校验、状态集中到一个 hub：一致性、可审计、渠道复用。
