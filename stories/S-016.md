**行业适用**：BNK direct · INT / TEL transferable（研发效能）

## Situation
- As the team grew, code review became a bottleneck: senior engineers spent too long on repeat reviews, and quality was inconsistent.
- Goal: faster, more consistent reviews without giving up human control.

## Task
- O1 + O2: I designed and built the service. It went live in May 2026.

## Action
- I built a Spring Boot orchestrator triggered by a pull-request webhook (Bitbucket / GitHub). It passes the three-dot diff to a headless Claude Code agent via ProcessBuilder.
- The agent reviews four dimensions (security, performance, correctness, maintainability), and SonarQube runs on every PR alongside it.
- Comments are posted back to the PR. A human reviewer approves and merges.
- I improved review quality through prompt A/B testing and AgentOps/LLMOps practice.

```
PR ─webhook─► Spring Boot orchestrator ─three-dot diff─► headless Claude Code agent
                   │                                   (security · performance · correctness · maintainability)
                   ├─► SonarQube scan                                 │
                   ▼                                                  ▼
            comments on PR ◄──────────────────────────────────────────┘
                   ▼
            human reviewer approves / merges (AI never does)
```

## Result
- Senior engineers' review time was cut by an **estimated ~80%**: human review rounds fell to 1–2 per PR, each about 30% as long, because the AI cleared syntax and basic issues and reviewers could focus on design and risk.
- How to say it: call it an estimate, explain the formula, and do not present it as measured telemetry.

## 讲法差异
- **ATL**：diff 范围控制、静态分析加 LLM 两层、prompt 评估方法。
- **SM**：研发效能投资：问题、投入、产出、治理（治理细节见 S-017）。
